# Local Google documentation style guides

Reference copy of Google's official documentation writing guides, committed to
the repo so the documentation skills can consult them without a network
round-trip.

## Usage

Before writing or editing any project documentation (README.md, GUIDE.md,
CHANGELOG.md, PATCH_SOURCES.md, commit messages), read the relevant file below
and apply its rules. The `docs-maintenance` skill owns this; every other skill
that writes documentation (patch-audit, patch-sweep, patch-cachy-branches,
kernel-build, kernel-version-bump) points here for prose style.

## Files

| File | Content |
|---|---|
| `google-docguide/style.md` | Google Markdown style guide — document layout, headings, lists, code, links, capitalization, punctuation in Markdown. |
| `google-docguide/best_practices.md` | Documentation best practices — say what you mean, simply and directly. |
| `google-docguide/philosophy.md` | Philosophy of the Google documentation guide. |
| `google-docguide/READMEs.md` | About writing README files. |
| `google-docguide/README.md` | The guide's own index. |
| `google-docguide/VERSION` | Guide version (2.0). |

The larger prose guide (voice, tone, word choice, punctuation) lives online at
<https://developers.google.com/style>; this folder carries the official
markdown-published portion.
